# Scraping Directory

This directory contains scripts for downloading and updating Steam game data from the Steam Storefront API and HTML pages.

## Overview

The scraping pipeline collects raw Steam data including:

- Game metadata (name, genres, tags, release dates)
- User reviews (for quality scoring and playtime analysis)
- Short descriptions and other storefront content

Data is collected with robust error handling and interruption tolerance.

## Components

### `download_steam_data.py`

Downloads bulk data from Steam's public endpoints:

- Gets full app list via `ISteamApps/GetAppList/v2`
- Downloads storefront metadata in batches
- Uses cookies to bypass age gates
- Caches raw HTML/JSON responses to avoid redundant downloads

### `scrape_steam.py`

Main scraping engine with sophisticated features:

- **Hierarchical Local Cache**: Stores raw responses, archives old data
- **Exponential Backoff**: Retries failed requests with increasing delays
- **Atomic Writes**: Writes to temporary files, only replaces production CSVs on success
- **English Prioritization**: Prefers English review counts for relevance
- **Checkpointing**: Can resume from last processed appid

### `build_scraped_dataset.py`

Post-processing script that:

- Merges newly scraped data with existing datasets
- Validates data integrity
- Handles conflicts and updates
- Archives old production files to `scraping/archive_csv/`

### Batch Files

- `scrape_from_start.bat` - Fresh scrape (archives existing data)
- `scrape_from_last_checkpoint.bat` - Resume from checkpoint

## Raw Data Cache

By default, raw scraped HTML/JSON is cached outside the repository to save space. The location is controlled by `RAW_DOWNLOAD_PATH` in `common/constants.py`. This cache can be reused across different repository instances.

## Output Files

Production data files (in repository root):

- `scraped_games.csv` - Game metadata (tags, genres, release dates, review counts)
- `scraped_reviews.csv` - Individual user reviews (for count repairs and playtime analysis)

During scraping, temporary files `*_inprogress.csv` are created. Only upon successful completion are these atomically renamed to replace the production files. Old production files are moved to `scraping/archive_csv/`.

## Running a Scrape

### Full Refresh

```bash
scraping/scrape_from_start.bat
```

### Resume from Checkpoint

```bash
scraping/scrape_from_last_checkpoint.bat
```

Or manually:

```bash
python scraping/scrape_steam.py
```

## API Key Requirement

A Steam Web API key is required. Set it in `.env` file:

```
STEAM_API_KEY=your_key_here
```

See `.env.example` for template.

## Important Notes

- The scraper targets the Storefront directly (HTML/embedded JSON) for high-fidelity tags and metadata, bypassing age gates
- Review counts are prioritized from English-language sources when available
- Games with 0 votes in all categories are dropped during dataset building
- The pipeline expects `data/pipeline_games_clean.csv` to exist (generated by `build_scraped_dataset.py`)
- All scraping operations are **append-only**; historical data is preserved via archiving

## Integration with Pipeline

The scraped data feeds into the pipeline via `generate_metadata.py`, which uses `data/pipeline_games_clean.csv` as the source of truth for all subsequent artifact generation.

## Troubleshooting

- If you see `scraped_games_inprogress.csv` lingering, a previous run may have been interrupted. You can safely delete it and restart.
- For API limit errors, check your Steam API key quotas and backoff intervals.
- If tag counts seem low (capped at 20), this is expected - Steam only returns the top 20 user tags. The pipeline's EM imputation handles missing tags.
